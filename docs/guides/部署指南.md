# 部署指南

## 方式一：使用预构建镜像（推荐，NAS / 通用 Linux）

适合群晖/威联通等 NAS、普通 Linux 服务器，开箱即用。

**步骤：**

1. 创建项目目录：
   ```bash
   mkdir docker-mcpilots && cd docker-mcpilots
   mkdir config secrets
   ```

2. 把 `docker/docker-compose.yml` 放到当前目录

3. 在 `docker-compose.yml` 中修改环境变量：
   - 修改 `ADMIN_PASSWORD` 为你想要的管理员密码
   - 修改 `PUID`/`PGID` 为你的用户 ID（群晖用户通常是 1026/100，其他系统用 `id` 命令查看）
   - 可选：设置 `INITIAL_API_KEYS` 初始 API Key（格式：name1:key1:role1,name2:key2:role2）
   - 可选：设置 `ADMIN_USERNAME` 修改默认管理员用户名

4. 启动：
   ```bash
   docker compose up -d
   ```

**配置文件说明：**

| 文件 | 作用 |
|------|------|
| `config/settings.yaml` | 服务端口、Docker socket 路径、功能开关 |
| `secrets/auth.yaml` | API Key、角色权限、容器范围（敏感文件） |
| `secrets/admin.yaml` | Web UI 管理员账号密码（敏感文件） |

**环境变量说明：**

| 变量名 | 说明 | 默认值 |
|--------|------|--------|
| `TZ` | 时区 | `Asia/Shanghai` |
| `PUID` | 运行容器的用户 UID | `1000` |
| `PGID` | 运行容器的用户 GID | `1000` |
| `ADMIN_USERNAME` | Web UI 管理员用户名 | `admin` |
| `ADMIN_PASSWORD` | Web UI 管理员密码（首次启动时设置） | 随机生成并警告 |
| `INITIAL_API_KEYS` | 初始 API Key 列表，格式：`name1:key1:role1,name2:key2:role2` | 无 |
| `MCP_SESSION_IDLE_TIMEOUT` | MCP HTTP 会话空闲超时。`none` = 永不过期（与旧版一致）；填秒数（如 `86400`）可回收孤儿会话 | `none` |
| `MCP_CONFIG_DIR` | 配置文件目录 | `/app/config` |
| `MCP_SECRETS_DIR` | 敏感文件目录 | `/app/secrets` |

### MCP 会话生命周期（v2.1.3 起）

MCP 的 Streamable HTTP 会话保存在**服务端内存**里，生命周期规则如下：

- **默认 `MCP_SESSION_IDLE_TIMEOUT=none`**：不做空闲回收。会话只在两种情况下销毁——客户端主动断开（`DELETE`），或服务端进程退出（重启容器 / 重启服务）。
- **设为秒数**（如 `86400`）：仅回收**既无在途请求、也没有打开的 GET/SSE 流**的会话；真正被回收时会记一条 INFO 日志 `Session <id> idle timeout`。适合长期运行、客户端反复重连留下大量僵尸会话的场景。
- **重启会使所有会话失效**：会话表在内存中，容器重启后客户端带着旧 `mcp-session-id` 请求会收到一次 `404 Session not found`，服务端日志为 `Rejected request with unknown or expired session ID: <id>`；客户端随后重新 `initialize` 即恢复，属正常现象，不是故障。
- **并发会话上限**：SDK 默认最多 10000 个会话，超出后新会话被拒绝并记 WARNING `Refusing to open a new session: N sessions are already open`。正常使用不会触及；若真的出现，说明客户端在泄漏会话，应设置空闲超时。
- **确认超时配置已生效**：启动日志里有一行
  `core.mcp_session: MCP HTTP 会话空闲超时：已关闭（会话永不过期）`（或 `...：86400 秒`）。

> 历史背景：`fastmcp` 4.1.0 起把默认空闲超时改成 1800 秒（4.0.x 是永不过期），曾导致 `transport session expired` / tools 列表为空。自 v2.1.3 起默认改回"永不过期"，并把全部依赖锁进 `requirements.lock`。

## 方式二：从源码构建镜像（开发者）

适合开发者本地调试，或需要自定义修改的场景。

```bash
git clone https://github.com/sopyk/docker-mcpilots.git
cd docker-mcpilots
docker compose -f docker/docker-compose-build.yml up -d --build
```

默认端口 8900，记得改 `secrets/auth.yaml` 里的 API Key。

## 方式三：VPS 宿主机直装

适合追求最低资源占用的场景，不需要 Docker 嵌套。详见 [VPS 部署](deploy-vps.md)。

## 支持的架构

| 架构 | 状态 | 适用设备 |
|------|------|----------|
| **linux/amd64 (x86_64)** | ✅ 已支持 | 群晖/威联通等 Intel/AMD 架构 NAS、大多数 VPS、普通 PC 服务器 |
| **linux/arm64** | ✅ 已支持 | 树莓派、Mac M 系列、部分 ARM 架构 NAS |
| **linux/arm/v7** | ❌ 暂不支持 | 老款树莓派等 32 位 ARM 设备 |

> 💡 预构建镜像同时提供 amd64 和 arm64 两种架构，docker pull 会自动拉取匹配当前 CPU 的版本。32 位 ARM（arm/v7）设备请自行从源码构建。
